### Problem Investigated
Whats Up ATL crashing with `isTTY` error in browser. Error: `dotenv/lib/main.js` calling `process.stdout.isTTY` which doesn't exist in browser.

### Investigation Results
1. **Git-committed source is CLEAN** - `transit/route.ts`, `weather/route.ts`, and `tripadvisor/route.ts` do NOT import dotenv in current HEAD (commit 905aa22)
2. **Committed versions ARE clean** - verified with `git show HEAD:src/app/api/weather/route.ts` and `git show HEAD:src/app/api/tripadvisor/route.ts` - no dotenv imports
3. **But deployed version has dotenv** - The production deployment `2wKZE59jv` was a "Redeploy of DBjaPJnVR" (from Mar 15). Redeploy uses the SAME source code as the base deployment, NOT the latest git.
4. **The Mar 15 deployment had dotenv** - Before any fixes were applied
5. **Vercel CLI deployment blocked** - Error: `Environment Variable "NEXT_PUBLIC_MAPBOX_TOKEN" references Secret "NEXT_PUBLIC_MAPBOX_TOKEN", which does not exist.` Even though NEXT_PUBLIC_MAPBOX_TOKEN is NOT in `vercel env ls` output.

### Root Cause
The fresh Vercel deployment (`2wKZE59jv`) was triggered as a "Redeploy of DBjaPJnVR". Redeploy reuses the OLD source code from the Mar 15 deployment. The Mar 15 source had dotenv imports in ALL API routes. The dotenv fix was only applied to transit/route.ts in the fix commit (`07a0fa7`), but weather/route.ts and tripadvisor/route.ts were never actually fixed in committed source (they still had dotenv in the original Mar 15 source).

But wait - verified git committed versions ARE clean now. So the issue is Vercel is not building from latest git, it's redeploying old source.

### Solution Needed
